# Criterio de evaluación - Sesión 08: Demo Day

> 📋 **Documento interno para el facilitador**
>
> En v3 la presentación se evalúa **en clase: 0 (no presentó) / 100 (presentó)**. No hay rúbrica ponderada, ni ROI obligatorio, ni rúbrica de pares. Este documento define qué cuenta como "presentó" (100).

## Información General

| Aspecto | Detalle |
|---------|---------|
| **Sesión** | 08 — Exposición / Demo Day |
| **Mini-proyecto** | Sustentar el proyecto integrador (5 min) |
| **Modelo de evaluación** | 0 / 100 (en clase) |

---

## Qué cuenta como "presentó" (100)

El estudiante obtiene **100** si sustenta su proyecto en clase con:

- [ ] Presentación de ~5 min con estructura **caso → demo → resultados → aprendizajes**
- [ ] **Demo en vivo** del sistema funcionando (o video de respaldo si falla en vivo)
- [ ] Un **resultado tangible** comunicado (tiempo ahorrado, costo o items procesados)
- [ ] Un **roadmap personal** (su próxima automatización)

> Obtiene **0** si no presenta.

---

## Señales de una buena presentación

- La demo muestra el sistema procesando datos reales, no solo slides.
- El resultado es concreto ("de 4 horas a 5 minutos"), no vago ("ahorro tiempo").
- El roadmap nombra un caso específico, no "seguir mejorando".

---

## Errores que NO penalizan

- Que la demo falle en vivo por internet/API: se acepta el video de respaldo o la explicación.
- Diseño visual imperfecto: se evalúa que funcione, no la estética.

---

## Notas para el facilitador

1. Lo esencial es que el estudiante **muestre su sistema y lo explique**. Si la demo falla, vale el respaldo.
2. El feedback del grupo es **constructivo e informal** (qué funciona + qué mejorarías), no una rúbrica calificada de pares.
3. El test diagnóstico (`test/`) es aparte y **no** afecta la calificación.
